For the last several years I've been helping teams answer one deceptively simple question: **"what is my system actually doing right now?"** Mostly on AWS and Kubernetes, mostly with OpenTelemetry, and always with strong opinions about what a good dashboard looks like.

Working on the vendor side of observability means I've seen *hundreds* of real production setups — the beautiful, the broken, and the "why is this Lambda logging 40GB a day". That's shaped how I think: telemetry isn't about collecting everything, it's about being able to answer questions when it's 3am and something's on fire. 🔥

Lately I've been deep into what **AI agents can do for observability** — agents that read your codebase and tell you where instrumentation is missing, agents that run investigations, agents that do the boring parts of the job so humans can do the interesting ones.

## 🔭 What I'm about

- **Observability** — OpenTelemetry (collectors, instrumentation, the works), logs/metrics/traces pipelines, and making telemetry actually *useful* instead of just expensive
- **AWS & Kubernetes** — EKS, ECS, Lambda, GitOps with Flux, infrastructure as code. If it runs in a cluster or a cloud, I want to know what it's telling us
- **AI agents for real work** — multi-agent systems built on Claude that analyze, investigate, and draft, with humans staying in the loop

## 🛠️ Things I've built

| Project | What it does |
|---|---|
| [**observability-copilot**](https://github.com/iagobanov/observability-copilot) | Point it at any repo and it finds your observability gaps — then hands you concrete OpenTelemetry instrumentation recommendations. Web UI or GitHub Action. |
| [**tam-central-hub**](https://github.com/iagobanov/tam-central-hub) | TAM-OS: a multi-agent system where every customer gets a dedicated AI agent that gathers context from Slack, Jira, Notion & more, then drafts weekly briefs. |
| [**cx-dataprime-batch**](https://github.com/iagobanov/cx-dataprime-batch) | Runs huge Coralogix DataPrime queries by chunking them in time, running chunks in parallel, and auto-splitting anything that hits the scan limit. |
| [**cx-centralized-observability-gateway**](https://github.com/iagobanov/cx-centralized-observability-gateway) | A centralized OpenTelemetry gateway for Kubernetes fleets — tail sampling, routing, and one place to reason about your telemetry. |
